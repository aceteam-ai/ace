# Workflow Engine v2 RC runtime

Ace's local graph contract follows the `aceteam://flows/graph-template` and `aceteam://flows/schema-overview` resources in the AceTeam MCP. The graph has `input_node`, `inner_nodes`, `output_node`, and `edges`; node parameters and ports should be checked with `flow_node_type_details`. The [workflow-engine library](https://github.com/aceteam-ai/workflow-engine) defines validation and execution, and the [v2.0.0rc16 examples](https://github.com/aceteam-ai/workflow-engine/tree/v2.0.0rc16/examples) are the versioned source for Ace's canonical bundled set: `addition`, `append`, and `error`. Their graph JSON is copied byte-for-byte into Ace; Ace adds only local listing metadata. The four older LLM graphs remain as Ace examples for existing CLI and chat flows. MCP's organization Flow list contains user-owned workflows and is not the source for this bundled set.

Ace pins the published [workflow-engine 2.0.0rc16](https://pypi.org/project/aceteam-workflow-engine/2.0.0rc16/) and [aceteam-nodes 0.8.0](https://pypi.org/project/aceteam-nodes/0.8.0/) in `~/.ace/venv-workflow2-rc16`. The old `~/.ace/venv` is left in place. The nodes package is a node source, not a runner: it advertises node entry points. Ace mounts Input, Output, LLM, and APICall into an isolated workflow-engine registry and executes with the node package's `CLIContext`. `ace workflow validate` checks the graph through the same registry, and `ace workflow list-nodes` reports the mounted local types.

The three workflow-engine examples are exact copies of the tagged library graphs. The 11 tasks and four Ace LLM examples are local graphs under the same v2 contract. None of these are described as copies of database-backed platform seeds. Platform templates stay versioned, authenticated catalog entries; Ace fetches their selected graph version and offers local execution only when its node types are mounted, while remote execution keeps its explicit credit review.

A credential-free check against the published packages validated all 11 task graphs, all 4 Ace examples, and all 3 tagged workflow-engine examples, executed `hello-llm` with a synthetic LLM context, and executed `api-to-llm` against a loopback HTTP fixture plus synthetic LLM context. No live model or platform account was used. The integration fixture can repeat these checks with `ACE_RC_PROOF_PYTHON` pointing to an isolated Python environment containing the pinned pair.
